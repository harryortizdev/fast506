======================================================================
  FLUJO DE LA FOTO DE PERFIL — FAST506
  Envío desde el formulario al backend y recuperación al iniciar sesión
======================================================================

------------------------------------------------------------------------
PARTE 1: ENVIAR LA IMAGEN DESDE EL FORMULARIO AL BACKEND
------------------------------------------------------------------------

1. El usuario selecciona una imagen en el campo de archivo del formulario
   (AdministratorForm.tsx).

   El input de tipo "file" captura el archivo:

       <input type="file" accept="image/*" onChange={handleImage} />

   El handler guarda el archivo en el estado local:

       const handleImage = (e) => {
           const file = e.target.files[0];
           setImage(file);                          // guarda el File
           setImagePreview(URL.createObjectURL(file)); // previsualización local
       };

2. Al hacer submit, el formulario construye un objeto FormData en lugar
   de enviar JSON. Esto es necesario porque HTTP no puede mezclar JSON
   con archivos binarios en el mismo body.

       const formData = new FormData();
       formData.append("name", form.name);
       formData.append("email", form.email);
       // ... demás campos ...
       if (image) formData.append("profileImage", image); // el File va aquí

3. El servicio frontend (AdministratorService.ts) envía el FormData
   con fetch. NO se pone el header "Content-Type" manualmente; el
   navegador lo agrega automáticamente como:

       Content-Type: multipart/form-data; boundary=----WebKit...

   Si se pusiera "application/json" manualmente el backend rechazaría
   la petición con error 415 Unsupported Media Type.

       fetch("http://localhost:8080/api/admins/update", {
           method: "PUT",
           body: formData,   // sin headers manuales
       });

4. El backend (AdministratorController.java) recibe la petición con
   la anotación:

       @PutMapping(value = "/update", consumes = MediaType.MULTIPART_FORM_DATA_VALUE)

   Cada campo del FormData se lee con @RequestParam y el archivo con
   MultipartFile:

       @RequestParam("name") String name,
       @RequestParam(value = "profileImage", required = false) MultipartFile profileImage

   El @RequestBody NO funciona con multipart/form-data; por eso se
   usa @RequestParam para cada campo individual.

5. El servicio backend (AdministratorService.java) guarda el archivo
   en disco dentro de la carpeta "uploads/" (relativa al directorio
   de ejecución del servidor):

       String fileName = UUID.randomUUID() + "_" + image.getOriginalFilename();
       Path path = Paths.get("uploads/" + fileName);
       Files.createDirectories(path.getParent());
       Files.write(path, image.getBytes());

   UUID genera un nombre único para evitar colisiones entre archivos
   con el mismo nombre original.

6. En la base de datos solo se guarda la ruta relativa como texto,
   NO el archivo binario:

       admin.setProfileImage("uploads/" + fileName);
       // Ejemplo: "uploads/a3f7c1d2-..._foto.jpg"

   El campo profile_image en la tabla users almacena ese string.


------------------------------------------------------------------------
PARTE 2: RECUPERAR Y MOSTRAR LA IMAGEN AL INICIAR SESIÓN
------------------------------------------------------------------------

7. Al hacer login (LoginController.java), el backend busca al usuario
   en la base de datos. El objeto User ya contiene el campo profileImage
   con la ruta relativa guardada en el paso anterior.

   Esa ruta se incluye en la respuesta JSON y también se guarda en la
   sesión HTTP para no tener que consultar la base de datos en cada
   petición a /me:

       session.setAttribute("profileImage", user.getProfileImage());

       response.put("profileImage", user.getProfileImage());
       // Ejemplo del JSON devuelto:
       // { "userId": 5, "name": "Juan", "profileImage": "uploads/a3f7c1d2-..._foto.jpg", ... }

8. El endpoint GET /api/auth/me (usado al recargar la página para
   restaurar la sesión) también devuelve el profileImage desde la
   sesión:

       response.put("profileImage", session.getAttribute("profileImage"));

9. El AuthContext (AuthContext.tsx) recibe ese JSON y lo almacena en
   el estado global de React como parte del objeto AuthUser:

       export interface AuthUser {
           userId: number;
           name: string;
           profileImage: string | null;  // ruta relativa o null
           // ...
       }

10. El Navbar (Navbar.tsx) construye la URL completa combinando la
    base del servidor con la ruta relativa guardada:

        src={
            user.profileImage
                ? `http://localhost:8080/${user.profileImage}`
                : "https://cdn-icons-png.flaticon.com/.../149071.png"
        }

    Si el usuario tiene foto:
        → http://localhost:8080/uploads/a3f7c1d2-..._foto.jpg

    Si no tiene foto:
        → imagen genérica de persona (fallback)

    Para que la URL http://localhost:8080/uploads/... funcione,
    el backend debe exponer la carpeta uploads/ como recurso estático.
    Esto se configura en WebConfig.java con addResourceHandlers.


------------------------------------------------------------------------
RESUMEN DEL FLUJO COMPLETO
------------------------------------------------------------------------

  FORMULARIO (React)
      │  FormData con campo "profileImage" (File)
      ▼
  fetch PUT /api/admins/update  (multipart/form-data)
      │
      ▼
  AdministratorController  (@RequestParam MultipartFile profileImage)
      │
      ▼
  AdministratorService
      ├─ Guarda el archivo físico en uploads/uuid_nombre.jpg
      └─ Guarda la ruta "uploads/uuid_nombre.jpg" en la BD (campo profile_image)

  ---------------------------------------------------------------

  LOGIN (usuario inicia sesión)
      │
      ▼
  LoginController POST /api/auth/login
      ├─ Lee profile_image de la BD a través del objeto User
      ├─ Guarda la ruta en la sesión HTTP
      └─ Retorna la ruta en el JSON de respuesta

  AuthContext (React)
      └─ Almacena profileImage en el estado global AuthUser

  Navbar (React)
      └─ Construye la URL: http://localhost:8080/ + profileImage
         y la usa como src del <img> del avatar
